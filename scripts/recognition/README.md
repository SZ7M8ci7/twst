# スクショから手持ちを取り込む

手持ち設定の「スクショから取り込む」で PNG / JPEG / WebP を選び、候補を確認して反映します。その後、既存の「保存」で確定します。画像の解析、照合、レベル OCR はブラウザ内で行い、スクショはサーバーに送信しません。処理の重い照合は Web Worker、OpenCV.js は必要時だけ読み込みます。

## 外部画像と更新

主な取得元は [日本語Wiki](https://twst.wikiru.jp/) です。`?cmd=list` でカードページを列挙し、既存の `wikiURL` と正確に対応付けます。519カード全件のページが対応しています。不足する絵柄は [Gamerchの日本語カード一覧](https://gamerch.com/twst/967287) から、レア度・キャラクター・衣装名が完全一致するページだけを自動取得します。既存アプリの一覧アイコンも正しいカードIDの補助テンプレートとして利用します。英語Wikiは使いません。画像類似度で辞書のカードIDを推測しません。

カード本文 `#body` の基本情報表とグルーヴィー欄から、通常・変化後の添付画像を区別します。結合濁点、全角記号、GROOVY表記、撮影ファイル名にも掲載位置で対応します。カード全体絵からORB特徴点を抽出し、スクショの一覧アイコンを部分画像として照合します。カードごとの手動トリミングは不要です。通常・変化後は同じカードIDへ統合し、異なるカード間の差で確信度を判定します。

1日1回、日本時間04:17（UTC 19:17）のGitHub Actionsでページと画像の更新を調べます。通常のpush・手動のアプリ公開では検証済みの公開辞書を再利用し、取得元へアクセスしません。辞書が存在しない初回のみ構築します。カード一覧・未完了カードページのHTTPキャッシュは24時間有効です。取得済み画像は期限を設けず再利用します。取得は直列で、主Wikiはリクエスト開始を1秒以上空け、Gamerchは各通信の前に1秒待機します。429・503応答後はその取得元の処理を終了し、同じ実行中は再試行しません。日次ではカード一覧から新規ページを検出し、新規・画像未取得・必要情報未掲載のカードだけ個別ページを確認します。通常・グルーヴィー後それぞれの取得済み判定データを公開辞書から引き継ぎ、両方取得済みのカードは個別ページにも画像URLにもアクセスしません。Gamerch由来の取得済み画像も同様です。条件付き取得は一覧と未完了カードページに限り、取得済み画像の差し替え確認は行いません。現行辞書は519カード中517カードの全体絵を含み、既存アイコンと合わせて1,547テンプレートです（2026-09-15）。画像がないこととカードの存在は別に記録します。画像取得失敗時はそのカードの最後の検証済み特徴量を維持し、全体取得失敗では最後に検証した版を使います。

新カードはページから基本情報・魔法・バディを読み、同じビルドで `chara.json` に追加します。既存IDと手持ち保存キーは変えません。新規IDはページ名から安定的に生成し、公開カタログを次のビルドで引き継ぎます。後から既存のカタログ更新に同じカードが含まれた場合も、Wiki URLで統合して保存キーを維持します。必要な能力値まで未掲載の新ページは更新レポートに記録し、次回再試行します。不明な値で既存値をゼロ上書きしません。新規カードの一覧画像がアプリ側の素材にまだない場合は既存の未掲載画像を表示し、素材の追加後に対応します。

公開データはschema 2のマニフェストとSHA-256で識別するオブジェクトです。特徴量をカードIDのハッシュで64分割し、カード・不足画像の追加時には変更された分割と索引だけを取得します。カタログも内容ハッシュで固定し、取得途中・失敗時に不完全な版へ切り替えません。カード全体絵はビルド側のキャッシュだけに置き、ユーザーへ配信しません。

[Wiki利用のガイドライン](https://twst.wikiru.jp/?Wiki利用のガイドライン) と [編集のガイドライン](https://twst.wikiru.jp/?編集のガイドライン) を確認しました。明示された画像引用上の条件を、外部への無条件な再配布許諾とは解釈していません。本機能の公開物は数値特徴量と出典URLです。カード画像の著作権は各権利者に帰属します。Wikiの構造変更・規約変更には追随が必要です。

## 解像度差と確認操作

画像を横幅と縦方向の分割領域に合わせて処理し、枠の繰り返しからカード領域を検出します。カード領域を正規化し、通常・グルーヴィー後の候補を同じカード ID にまとめます。低い確信度、枠の欠落、途中で切れた画像は自動確定しません。元画像上で領域を囲み、検索からカードを選び直すこともできます。

同じカードの重複は1枚に統合。所持は追加し、スクショに写っていないカードは変更しません。レベルは左右を常時読み取り、現在値/上限値の左側を現在レベル、右側を最大レベルとして別に保持します。取り込み画面の「取り込むレベル」で最大レベル（初期値）／現在レベルを選択でき、結果欄・確認対象・重複チェック・手持ち反映は選択した値に揃えます。手修正は選択肢ごとに保持し、切り替えても失いません。読み取れない側をもう一方で補わず、未確認として保存済みレベルを維持します。凸数判定用の最大レベルはOCRの元値を保持します。数値帯の背景を除き、装飾・Lv文字と数字を分離し、通常の一行OCRで確信できない場合はRaw Lineでも確認し、さらに数字を分割して一文字ずつ確認します。選択した側の値が読めたカードは反映時に既存レベルを更新し、読めなかった場合は維持します。黒い外枠は4凸、非黒枠で3つの属性マークがある場合は3凸です。SSRでM3未解放の場合に限り、最大レベル80〜84は無凸、106〜110は2凸と判定します。SR・Rには最大レベルによる判定を適用しません。それ以外は不明（0〜2凸）として表示し、反映時には0凸を指定します。カードを選び直してレア度が変わった場合は最大レベル由来の判定を再計算しますが、手動で修正した凸数は保持します。同一カードの重複でレベル・凸数が矛盾する場合、その項目の更新を保留します。

「今回の反映を取り消す」は、取り込みで変更したカードのみを復元します。取り込み後に別の編集を行ったカードは復元対象から外します。キャンセル中や解析エラー時に、途中の検出結果を所持へ反映しません。

画像枚数にアプリ側の上限はありません。各30MB・2400万画素・一辺24000pxまで。各画像のカード領域は300個までです。WebAssembly / Worker / Canvas / Web Crypto を利用できる現行ブラウザを想定しています。


Python 3.11をCIで使用します。OCRランタイムと数字を含む英語文字認識用データは `predev` / `prebuild` でパッケージからコピーし、同じサイトから配信します。英語Wikiの画像・カードデータは使いません。

ブラウザ側は画像の形式・署名・サイズ・寸法を先に検証し、有効な画像がある場合だけ辞書とエンジンを読み込みます。解析終了・キャンセル時は認識WorkerとOCR Workerを終了し、画像Bitmapも解放します。辞書とOCRの再利用キャッシュは残します。

特徴量は現行版で約99.6MBです。初回に取得し、以後は64分割のうち変更分だけを更新します。旧抽出形式のキャッシュが残っていても、検証済みの新形式へ切り替えます。旧640点版でのローカルChrome検証では、2回目はマニフェストの条件付き確認1件（304、本文0バイト）で、特徴量・OCRの追加転送は0でした。アプリ起動・手持ち画面表示・モーダル表示・無効なPNG選択まで、辞書と認識エンジンへの通信は0件です。実回線・端末の性能によって待ち時間は変わります。

認識関連テスト、Python更新処理、既存手持ち保存、Vue型検査、本番ビルドで検証しています。実投稿11画像の207枠と縮小・再圧縮54枠では現在レベル・凸数の261件が一致しました。カードの同定は別評価です。48/64/96/160pxの通常・変化後の実投稿切り抜きでも候補IDを検証しています。添付画像でのカード同定精度は下記に記録します。Safari/Android実機は未検証です。

辞書形式・特徴抽出条件を変える場合は Python と TypeScript の `EXTRACTOR` を同時に更新してください。OpenCV.js のバージョンも固定しています。OCRランタイムの更新時は `recognition-runtime/v7` の版も変更し、旧Service Workerキャッシュとの混在を防ぎます。

## 取得元アクセスの確認（2026-09-15）

旧設定は毎時実行に加えpushでも取得し、有効期限1時間を過ぎた全ページ・画像に条件付きリクエストを送っていました。304でもリクエスト自体は発生します。約519ページと約1,000画像なので、毎時実行は不要な負荷になるため日次へ変更しました。ブラウザの利用者が増えても取得元へのリクエストは増えません。

主Wikiのrobots.txtは2026-09-15の取得時点で全体禁止・Crawl-delay指定なしでした。Gamerchと画像CDNのrobots.txtはHTTP 202・空本文で確認できませんでした。取得元の許容負荷や過去の実リクエスト総数は確認できておらず、問題がなかったと断定するものではありません。今回の通信制御のテストはモック応答で行い、確認のための全件再取得は実行していません。

### 取得完了後の再アクセス廃止

日次更新はカード一覧を1件確認し、未登録カード・通常またはグルーヴィー後が未取得のカード・必要情報の掲載待ちだけを巡回します。全カードの両絵柄が揃って新規追加もなければ、外部確認は主Wikiのカード一覧1件だけです。Gamerchの一覧も不足画像がある場合だけ確認します。既存画像の差し替え確認・既存カード情報の定期再取得は行いません。

完了判定には一時的なHTTPキャッシュではなく検証済みの公開辞書を使うため、GitHub Actionsの画像キャッシュが削除されても取得済み画像を再ダウンロードしません。公開辞書と元画像キャッシュの両方が失われた場合や互換性のない抽出形式への移行時は、復旧・再構築が必要になる場合があります。新規カードの発見には引き続き一覧ページを確認しますが、全カードの個別ページを開く処理ではありません。

`test_incremental.py`は空のHTTPキャッシュと検証済み辞書から実際の更新処理を実行し、全件完了時の通信対象が一覧1件だけであること、新規カード・片方だけ不足の画像を追加すること、次回は取得しないことをモック通信で検証します。取得済みの判定データと辞書バージョンが不要に変化しないことも確認します。日次レポートには対象ページと巡回を省略した完了ページ数を記録します。
